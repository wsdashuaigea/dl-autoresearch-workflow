# Prompt 3：Codex 复现与持续优化

先将所有占位符替换为你已获授权的资源信息。**不要把填入真实 SSH 地址、凭据、私有路径或实验结果后的版本提交到公开仓库。**

```text
请按照以下流程完成论文复现、方法改进、训练和实验评估。

项目路径：[填写已授权目录]
论文及代码仓库：[填写]
SSH 主机：[填写已授权主机；不要在公开记录中写凭据]
数据集路径：[填写已授权路径]
目标指标：[填写指标、方向和评价协议]
实验预算：[时间/次数/费用]
停止条件：[目标、预算上限或连续无进展轮数]

阶段一：环境检查
- 连接已授权服务器，检查 GPU、CUDA、Python、依赖和可用空间。
- 核对项目代码、数据和评价脚本的完整性与访问权限。
- 优先复用已有环境，不影响服务器上其他项目或用户。

阶段二：原论文复现
- 理解代码结构、运行入口和原论文的评价协议。
- 固定代码版本、配置、随机种子和数据划分，复现基线。
- 比较复现指标与论文指标，并记录差异及可能原因。
- 保存配置、原始日志和结果，不覆盖已有实验。

阶段三：自主改进
- 根据基线和相关工作提出可验证的改进假设。
- 每轮记录一个主要改动，执行训练或推理实验。
- 自动提取指标，并在相同数据、预算和评价协议下比较。
- 有证据支持的改动保留；无效或有问题的改动回滚。
- 根据实验反馈决定下一轮实验；不要把一次偶然提升视为结论。

阶段四：实验管理
- 可使用 tmux 等工具保持训练会话。
- 监控 GPU、显存、训练进度与错误日志。
- 避免多个实验相互覆盖或抢占资源。
- 每轮记录假设、代码版本、配置、数据划分、指标、耗时与结论。
- 优先做低成本实验，再开展完整验证与必要的重复运行。

阶段五：结果整理
- 汇总所有实验，包括失败和无提升的实验。
- 输出最佳代码版本、配置、模型权重位置和原始日志位置。
- 生成基线与改进方法的指标对比，标明随机种子和重复次数。
- 给出必要的消融实验、尚未解决的问题和后续建议。

重要约束：
1. 不允许修改评价协议或数据划分来人为提升指标。
2. 使用验证集进行方法选择，保留独立测试集用于最终评估。
3. 不允许虚构实验结果、论文内容或相关工作。
4. 在已授权的目录、计算资源和预算范围内自主推进。
5. 不得擅自删除重要文件、修改系统配置或干扰其他用户。
6. 达到目标、耗尽预算或达到停止条件时停止，并总结结果。
7. 如果缺少访问权限或关键输入，说明阻碍并完成仍可进行的检查。

现在先检查项目和远程环境，然后开始执行。每轮使用实验记录模板留下可追溯记录。
```
