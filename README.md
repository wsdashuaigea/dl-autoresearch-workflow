# 深度学习 AutoResearch 工作流

一套用于深度学习科研的 AI 辅助工作流：从论文筛选、基线复现，到低成本改进、实验记录和成果评估。示例配置为 GPT Pro、Codex 和单张 RTX 4090；流程也可按实际硬件与预算调整。

> 这是一份通用公开模板。它不包含具体研究课题、私有代码、服务器地址、数据、实验结果或未公开的方法设计。AI 的建议和输出需要由研究者核查；指标提升本身不等于论文创新。

## 适用场景

- 希望复现近两年的深度学习开源论文。
- 需要管理 Linux 环境与远程训练，希望减少重复的环境配置与实验操作。
- 只有单卡 GPU，需要先做低成本验证，再决定是否扩大实验。
- 希望让每次改动都留下可追溯的代码、配置、日志和指标。

## 工作流程

| 阶段 | 目标 | 最低交付物 |
| --- | --- | --- |
| 1. 选择论文 | 找到代码、数据和评价协议公开且单卡可运行的工作 | 论文与仓库链接、资源估算、复现风险 |
| 2. 理解方法 | 弄清任务、模型、创新点和局限 | 方法流程、关键代码入口、可验证的改进假设 |
| 3. 复现基线 | 在相同评价协议下运行原方法 | 代码版本、配置、日志、复现指标 |
| 4. 验证改进 | 一次改变一个关键因素，先跑低成本实验 | 对照实验与消融实验记录 |
| 5. 迭代决策 | 根据证据保留或回滚改动 | 每轮假设、结果、结论与下一步 |
| 6. 整理成果 | 检查公平性、重复性和创新性 | 最优代码与权重、指标表、未解决问题 |

**核心循环：**论文筛选 → 理解原文 → 基线复现 → 自动改进 → 实验验证 → 继续迭代。

## 如何使用本仓库

1. 阅读 [论文筛选 Prompt](prompts/01-paper-selection.md)，核实论文、代码、数据和授权条件。
2. 用 [论文分析 Prompt](prompts/02-paper-analysis.md)梳理原方法，并制定少量可检验的改进方案。
3. 在**已获授权**的项目目录与计算资源上填写 [Codex 实验 Prompt](prompts/03-codex-experiment.md)中的占位符，先复现基线，再按预算开展实验。
4. 每轮复制 [实验记录模板](templates/experiment-log.md)，记录配置、代码版本、数据划分、原始日志和结论。
5. 用 [成果评估 Prompt](prompts/04-paper-readiness.md)检查证据是否足以支持论文写作。

Prompt 是起点，不保证论文能够复现或得到改进。论文、仓库、数据集和相关工作链接应实际检索并人工核实；不要把模型猜测当成实验事实。

## 实验原则

- **先固定基线。** 保存原论文的代码版本、依赖、随机种子、配置和评价脚本。若复现指标不同，先查明原因。
- **保持公平。** 不更改数据划分或评价协议来制造提升；验证集用于方法选择，独立测试集留作最终评估。
- **控制变量。** 每轮写清假设与改动，优先做小规模试验；正式结论需要对照、消融和必要的重复运行。
- **尊重资源边界。** 明确实验次数、时间与费用预算；检查 GPU 使用情况，避免和其他任务争抢资源。
- **保留证据。** 记录失败实验，保存原始日志与代码提交。报告真实结果和不确定性，不虚构指标。
- **保护隐私。** 不在公开 Prompt、日志或仓库中提交 SSH 地址、密钥、令牌、私有路径、未公开数据或研究方案。

远程训练可以使用 `tmux` 等工具保持会话；多人或多 Agent 并行时，应先协调 GPU 使用。完成实验后，由研究者判断方法是否有真实创新，是否需要补充重复实验、消融实验与相关工作比较。
